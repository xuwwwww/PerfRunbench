# PerfRunbench v0.3.0 Release Notes

PerfRunbench v0.3.0 packages workload-aware serving autotuning for
`llama-server` as a guarded release candidate. The release keeps the v0.2
golden path and adds serving-specific recommendation, explain, dry-run, and
Passport workflows.

## Highlights

- Validated C7g server plus T4g remote-client serving topology.
- `slots4-cont-on` serving profile packaged as a workload-scoped
  recommendation.
- `autotuneai serve recommend` for sanitized RecommendationBundle output.
- `autotuneai serve explain` for evidence, guard, and limitation summaries.
- `autotuneai serve run --best --dry-run` for no-search, no-mutation reuse
  checks.
- Serving Performance Passport schema with explicit protocol separation.
- Hard-drift guards for model, server, capability, architecture, CPU count,
  memory class, topology, workload, concurrency, CPU assignment, slots,
  continuous batching, context, network path, artifact identity, and cleanup.
- Public demo documents that do not require live AWS access.

## Recommendation Scope

Created recommendation classes:

- `maximum_throughput_remote`
- `interactive_latency_remote`

Created workloads:

- `interactive-short`, concurrency 4
- `decode-heavy`, concurrency 4
- `prefill-heavy`, concurrency 4

No recommendation is created for balanced multi-user, shared-prefix,
memory-constrained, or remote network tuning. Network tuning was skipped
because network-bottleneck evidence was absent.

```text
network_tuning_status: network_tuning_not_executed_evidence_absent
```

## Usage

```bash
autotuneai serve recommend \
  --workload interactive-short \
  --concurrency 4 \
  --recommendation-class maximum_throughput_remote

autotuneai serve run \
  --best \
  --workload interactive-short \
  --concurrency 4 \
  --dry-run
```

## Claim Boundary

Supported wording:

```text
Best observed eligible serving configuration under the tested C7g server,
T4g remote-client topology, Qwen2.5-7B Q4_K_M model, pinned llama-server
binary, workload, concurrency, and measurement protocol.
```

Do not claim a universal `llama-server` optimum, a general Graviton result, a
network-tuning improvement, or a combined speedup with `llama-bench`, loopback,
kernel, page-size, allocator, or build-profile protocols.

## Known Limitations

- No PyPI publication is performed by this release-candidate branch.
- The validated serving result is preliminary and single-topology.
- Concurrency 8 was not executed in Phase 21D2B.
- Remote network tuning was not executed because bottleneck evidence was
  absent.
- The T4g client did not contain the GGUF model.
- v0.2 Performance Passport artifacts remain valid as their original passport
  kind; the serving passport is a separate schema.
