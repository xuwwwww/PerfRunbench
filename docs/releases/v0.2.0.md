# PerfRunbench v0.2.0 Release Notes

PerfRunbench v0.2.0 is a release-candidate package for the golden-path
benchmarking and autotuning workflow:

```text
init
-> doctor
-> run --auto
-> RecommendationCache reuse
-> process-scoped apply/canary/rollback
```

## Highlights

- Golden-path CLI for fresh users.
- `autotuneai doctor` readiness checks that do not launch the workload.
- RecommendationCache with exact-match, soft-drift, hard-drift, missing,
  expired, revoked, corrupt, and ambiguous states.
- Automatic cache reuse through `run --auto` and no-retune reuse through
  `run --best`.
- PyTorch training adapter with bounded training slices.
- Effective batch guard for semantics-preserving training candidates.
- Safe training candidate execution that preserves failed candidates instead
  of converting them to zero metrics.
- ArmTune `llama.cpp` build/runtime tuning subsystem.
- Performance Passport generation and verification.
- Guarded process-scoped recommendation apply with validation, dry run,
  canary, lease, status, and rollback.
- CPU affinity hex-mask normalization.
- Installed-wheel release smoke across Windows x86_64, Linux x86_64, and Linux
  Arm64 CI runners.

## Measured Arm Inference Snapshot

Single target, single model, preliminary evidence only:

- target: AWS C7g / Graviton3 / Neoverse-V1
- workload: Qwen2.5-7B Q4_K_M with pinned `llama.cpp`
- `llama-bench` portable-baseline decode median: `10.825 tok/s`
- `llama-bench` arm-native decode median: `17.530 tok/s`
- `llama-bench` arm-optimized decode median: `17.380 tok/s`
- runtime-search baseline decode median: `13.630 tok/s`
- selected runtime candidate decode median: `17.480 tok/s`
- observed runtime-search improvement: `28.246515%`
- `llama-server` portable-baseline TTFT median: `97.260 ms`
- `llama-server` arm-native TTFT median: `62.826 ms`
- Performance Passport: `eligible_preliminary`
- Passport verification: passed
- guarded apply validation: passed

These results come from separate protocols. Do not combine build-profile,
runtime-search, and server-latency improvements into one aggregate speedup.

Recommended wording:

```text
Best observed eligible configuration under the tested Arm target, model,
inference workload, and measurement protocol.
```

## Synthetic And Fixture Boundaries

The public PyTorch training validations use synthetic workloads to validate
adapter mechanics, cache behavior, hard-drift refusal, bounded slices,
process-scoped apply, and cleanup. They are not model-quality or production
training-throughput claims.

CI fixture benchmark outputs must remain fixture evidence. A fake workload on
a real Arm64 runner is still `result_origin: test_fixture`.

## BootTrace

BootTrace prompt research and firmware-log model qualification were split into
the standalone BootTraceBench project. BootTrace is not part of the default
PerfRunbench candidate eligibility path.

## Known Limitations

- No PyPI package is published from this release-candidate branch.
- License metadata is not declared in this repository state.
- Arm inference evidence is preliminary and limited to one target/model/source
  commit/protocol set.
- T4g, C7g, and Windows results must not be compared directly.
- PyTorch is optional and intentionally not installed by required CI release
  smoke jobs.
- System-scoped tuning is not part of the default golden-path apply workflow.
- Android, mobile targets, new cloud automation, and additional model ladders
  are out of scope for v0.2.0.
